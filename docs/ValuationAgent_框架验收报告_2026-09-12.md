# ValuationAgent 框架验收记录

验收日期：2026-09-12。对象：当前工作区中的 0.1.0 后端实现。验收依据为本项目的[架构与实施计划](./ValuationAgent_架构与实施计划.md)，尤其是第 463 行的“框架完成”标准，而不是比赛官方评分表。

**结论：后端演示基础通过，完整框架闭环暂不通过。**

现有分层值得保留：CLI 和 FastAPI 共享 Runner，金融计算与页面分离，工作流产生真实事件，结果可持久化。当前实现仍以固定计算流程为主，LLM 负责计划文字、摘要和结果解释。它尚未实现我们要求的“对话驱动操作、工具决策、复核恢复、假设版本与重算”。Web 前端未交付。

不把尚未交付的正式金融模型、全市场取数、通用 OCR 或高级增长预测算作本轮必须完成的模型功能。但为了让金融团队后续接入，数据、工具和状态接口必须先完整；目前这部分也有缺口。

**3. 必须修正的具体问题**

以下 A/B 是本次修复优先级，与计划文档里的 P1/P2 开发阶段不同。

**A1：默认 demo 会替换提交的数据，且“上传假设”可以被忽略。**

复现：提交收入 200 亿元的结构化快照，省略 `mode`。请求被接受，存储的请求仍显示收入 200 亿元，但计算使用合成样例的 100 亿元，首年收入输出 108 亿元，而不是按所提交数据计算的 216 亿元。

另外，`assumption_source="upload"` 且没有文件时，任务仍以默认假设完成，而不是指出输入缺失。

原因：schemas/models.py 第 114 行默认 demo；workflow/graph.py 第 145 行优先载入合成数据；假设来源仅定义枚举，没有进入对应处理流程。

建议：demo 必须显式选择；对 demo 与真实输入混用明确拒绝或显式确认其语义。按来源严格检查历史数据和假设数据；缺少文件或未实现解析器必须返回明确状态。实际使用的数据来源和数据模式进入独立结果对象。

**A2：当前还没有有效的 Agent 工具决策链。**

`OpenAICompatibleClient.complete()` 只发送 messages，不发送工具 schema、不处理 tool_calls，也不验证结构化决策。规划节点把文字写入 `plan` 后，没有节点读取它。两组不同模拟计划均得到相同的工具序列。

固定金融校验和确定性计算顺序本身是合理约束；需要补的是受约束的决策能力，例如识别缺失字段、选择注册的数据工具、提交复核、解释方法适用性。不能依赖自由文本计划充当可执行控制。

建议：先实现一条可验收的“LLM → 类型化工具调用 → 参数校验 → 工具结果 → 状态更新”链路；金融算术继续交给确定性函数。注册工具的能力、输入输出 schema、错误类型和事件格式要统一。

**A3：暂停、对话和重算尚未形成闭环。**

- 缺失 `POST /api/runs/{run_id}/reviews`、`resume`、`revisions`。
- 图直接 `compile()`，没有持久化检查点和恢复逻辑。
- 问“把 WACC 改为 8%，重新估值，并保留旧版本”，回答仍是原 WACC 9.50%，结果不变。
- 历史消息虽然存入数据库，但 LLM 回答时只收到系统说明和当前问题，没有历史对话。

建议：区分“解释已有结果”和“修改任务”；为修改创建 revision，保存原因与变更字段，并按依赖重算。复核更正后恢复执行，保留前一版本和审计记录。CLI 和 Web 调用同一应用层方法。

**A4：合法基准参数可能被内部情景拖垮；没有估值也可能显示完成。**

复现：WACC=4%、g=3% 的基准条件满足 g<WACC，但系统自动生成的乐观情景变为 WACC=3%、g=3.5%，导致整个任务 failed。

另一复现：只选 P/E、没有同业样本，结果明确写“当前没有可用的估值区间”，任务状态却是 completed。

建议：对生成的每个情景独立校验，并通过明确政策处理无效情景，保留合法基准的诊断信息。结果汇总必须检查所选方法是否实际形成估值；全部不可用时进入待补数/未完成状态，不能作为正常估值成功展示。

相关位置：finance/reference.py 第 236 行；application/runner.py 第 54 行。

**A5：LLM 摘要未经数字校验，错误描述可以成为正式结果。**

模拟 LLM 返回“DCF 每股价值为 999999 元，数据已经金融专家核准”，系统原样保存。实际结构化 DCF 为 31.0707 元/股。这是故障注入检查，不代表已经观察到某个真实供应商产生上述回答。

建议：关键数字、模式和审核状态由结构化字段渲染；自由文本引用数值时使用引用 ID 或类型化结论，再进行一致性校验。未经核准的模型状态不能由生成文本更改。

相关位置：workflow/graph.py 第 361 行。

**A6：供应商报错可能把密钥带入事件和错误结果。**

正常模型配置只保留在内存中，但错误处理直接保留供应商响应正文。用纯本地模拟供应商返回“invalid key + 合成密钥标识”，该标识进入任务 error 和事件。因此 README 中“API Key 不写入事件或响应”的绝对表述目前不成立。

建议：对外部错误先做结构化归类和脱敏，再写入日志、事件、接口响应或摘要；不直接拼接响应正文。用合成密钥建立回归样例。

相关位置：llm/client.py 第 43 行，workflow/graph.py 第 89 行，application/runner.py 第 62 行。

**B1：插件协议存在隐式依赖，后续模型接入仍可能改动工作流。**

只实现 FinancialModelPlugin 声明方法的插件，snapshot 运行成功；demo 失败，报缺少 `demo_financials`。工作流直接使用了协议没有声明的方法。

建议：演示数据移到独立数据提供器。保留金融插件边界，补充数据获取、文件提取、收入预测、资本成本、同业筛选、区间政策和报告导出契约；允许未实现工具明确返回不可用，不要求本轮填完模型。

相关位置：core/plugins.py 第 19 行，workflow/graph.py 第 146 行。

**B2：数据契约和复算信息不足。**

- FinancialSnapshot 只有单期少量字段；没有多期财务、数据单位、报表口径、公告日期、页码/单元格、逐字段来源。
- ValuationOutput 不含企业、估值日、币种、模式和输入哈希。完整 RunRecord 可以提供部分上下文，但单独 results 接口没有这些字段。
- 大部分工具事件没有输入输出数据引用；不能仅靠事件重建中间结果。
- Decimal 在 JSON 序列化时转 float。输入 `10000000000.123456789`，存储再读为 `10000000000.123457`，无法保持精确原始输入。

建议：先确定最小数据字典、EvidenceRef、有效输入快照、AssumptionRevision 和结果元数据，再接教授的模型。金额持久化使用十进制字符串或约定精度的定点值。

相关位置：schemas/models.py 第 13、71、226 行；workflow/graph.py 第 68 行。

**B3：预测期间与历史基期未衔接。**

当前样例基期为 2025-12-31、估值日为 2026-09-12，第一行却标为 2027，只对 2025 年收入应用一次 8% 增长。没有补齐 2026 过渡预测，也没有明确剩余期间折现政策。

建议：由金融团队明确历史末期、首个预测期、估值日和折现时点规则；框架为这些规则保留明确字段。参考模型也应做到样例年份自洽。

相关位置：finance/reference.py 第 191、216 行。

**B4：失败重执行可能留下上一次结果。**

先成功执行，再注入计算失败并对同一 run 调用 execute：任务变为 failed，但旧 result 仍保留。当前 results 接口只判断结果是否为空，可能继续返回旧结果。

建议：禁止对已完成 run 无版本控制地执行；新增 revision/attempt 并明确结果所属版本。查询结果时同时检查状态和结果版本，避免将旧结果作为本次执行产物。

相关位置：application/runner.py 第 34 行；storage/sqlite.py 第 104 行；api/main.py 第 164 行。

**4. 补齐框架的实施顺序**

1. 修复输入模式、上传假设路由、无有效估值状态、情景边界、摘要一致性及错误脱敏，确保演示不会给出误导性的“成功”。
2. 固定数据与工具契约：历史多期、单位/口径/日期、EvidenceRef、AssumptionRevision、ModelResult、ToolSpec、数据提供器与报告适配器。
3. 实现一个受约束的 Agent 工具循环，以及提交复核、恢复、假设修改和依赖重算。持久化运行状态，保留不可变旧版本。
4. CLI 增加持续对话与实时事件订阅；Web 接入同一请求、事件、结果与复核 API，再实现颜色、比例、聊天区域和执行视图。
5. 接入金融团队批准的规则和基准案例；取数、PDF/Excel 解析及报告导出按契约逐项替换，不能把这些能力默认为已完成。

不需要推翻已有 Python 分层、Runner、事件协议和参考计算。主要工作是补齐被界面和金融插件共同依赖的控制与数据结构。

**5. 下一轮框架通过的可执行标准**

- CLI 和 Web 均能表达历史数据来源 × 假设来源四种组合；尚未接入的适配器明确阻断，并允许通过更正补充结构化数据继续。
- 至少一个真实模型供应商完成类型化工具调用，而非只生成计划和摘要；保存调用与结果引用。
- 输入一个缺失字段样例，系统定位问题、提交复核，用户更正后继续，记录更正依据。
- 用户在对话中修改 WACC：生成新版本，只触发 DCF、相关敏感性、区间比较与报告等受影响部分；旧版本可查。
- 独立插件只依赖公开契约即可替换；演示数据不依附金融模型。
- CLI 执行时即时显示工具状态；Web 对话与执行时间线来自同一运行事件；SSE 断线恢复无丢失或重复显示。
- 每份独立结果携带企业、日期、币种、模式、版本、假设与证据引用；无法估值时如实表示未完成。
- 上述故障样例进入回归验收，正常场景和失败恢复都通过。
- 金融负责人以明确版本的 Excel 或其他独立基准验证参考模型/正式模型，再单独进行金融模型验收。

当前适合作为继续开发的后端原型，不适合宣布完整 Agent 框架验收通过。
