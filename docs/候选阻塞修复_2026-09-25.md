# 候选阻塞修复与验证范围

## 适用范围

本次修复的是公司无关的证据绑定、候选恢复和估值提交逻辑，没有证券代码、公司名称或具体年报数值的专用分支。继续使用现有 `economic_agent` Conda 环境；没有改动 Tushare 模块，也没有新建 Python 环境。

## 行为变化

- 优先匹配原始科目名。营业收入与营业总收入、利息费用与利息支出不会再因为别名匹配顺序而互相抢占；标准字段名对应多行时必须缩小引文。
- 按明确表头识别年度、附注编号、同比列和本期/上期列；缺列、错年、单位冲突仍阻断。没有表头时不能默认第一个金额属于目标年度。股本金额不能作为普通股股数。
- 跨页依据按实际页码排序，而不是下载追加顺序。表头只沿连续已加载页关联；附注章节只能补充口径依据，不能带入远处表格的金额单位。长工作表保留所属工作表的表头，不向其他工作表借用。
- 全部候选有警告时向 LLM 返回逐项补证反馈，继续读取或搜索，而不是弹出无法确认的卡片。每轮最多三次全警告补证提交；仍无法核实就保留进度并显示具体原因和可执行的恢复选项。
- 相同提取重试不会无限新增同一候选。更正仍需确认，旧记录及工具事件保留。与所选估值方法无关的候选不再阻塞计算；必要字段缺失、相关冲突、未确认的关键假设仍阻断。
- 对已有可确认卡片，明确的“确认本批无警告字段”“直接确认开始估值”等输入等价于点击该卡片的确认按钮。只处理卡片中重新核验通过的字段；否定、疑问或附带修改的文字不触发确认。
- 旧会话继续时重新核验未确认字段，记录 `facts.revalidated`。确认旧卡片前也重新核验，不能依赖旧版“无警告”标记绕过来源检查。

## 验证

最终完整回归：258 项 Python 测试通过（约 186.72 秒）；网页 8 项状态测试、9 项组件检查通过，生产构建成功。

新增 `tests/test_evidence_recovery.py`，使用四个明确为合成的公司样本与不同表格分隔方式验证公共逻辑。覆盖错年、错单位、相近科目、空列、附注号、跨页、倒序追加页、长工作表、母公司口径、现金流标签换行、负数粘连、警告反馈、重复候选、旧会话恢复及自然语言确认。

同时验证四个连续年度的合成财务资料经过提取确认后，能在保留不相关待核对记录的情况下提交 DCF、执行确定性估值并导出 Excel 报告；没有把不完整资料或警告字段当作完整财务输入。

真实故障会话使用原数据库只读读取，再在临时测试目录中复制回放，未修改用户原会话。结果：13 个候选中 9 个通过重新绑定，8 个与当前 DCF 有关的字段出现在可确认卡片中；仍为 0 个已确认、未发起正式估值。剩余证据问题没有被强制忽略。本机该次重核约 0.55 秒，非性能承诺。

复核命令：

```powershell
conda activate economic_agent
python -m pytest -q
cd web
npm test
npm run test:components
npm run build
```

网页测试包括 8 项数据/状态测试、9 项虚拟 DOM 组件检查；不是实际浏览器点击或视觉验收。本次没有新增运行时依赖。

## 使用旧会话

1. 重启 CLI 或网页后端，以加载修改后的代码。
2. 恢复原研究会话；CLI 可使用退出时显示的 `valuationagent research --resume <research_id>`。
3. 重新连接模型。密钥不保存在数据库，恢复会话不等于恢复模型凭证。
4. 输入“继续”。系统重新核验旧候选，有可靠依据的显示可确认卡片，其余继续补证。

## 未扩大宣称的能力边界

- 本次模型编排回归使用脚本化模型，真实会话回放不调用远程模型；没有把这些测试宣称为多家真实公司的联网 LLM 全流程验收。
- 扫描 PDF 的 OCR、不能可靠对应的复杂多层表头、缺少原始披露、没有足够财务历史或未经确认的经营假设，仍需补充资料或明确复核；不会凭模型猜测或默认零值补齐。
- 自动估值仍以所选方法的必要输入、财务勾稽和专业校验为准。解除解析误拦截不等于任何公司的资料都足以立即出具可靠估值。
