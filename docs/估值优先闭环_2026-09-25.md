# 估值优先：从整理资料到模型交付

## 问题与修正

旧流程一旦找到一批有效财务候选就终止本轮并要求确认。提交估值工具还会因为回合开始时输入不齐而被移出工具列表。再加上默认开场要求“梳理历史数据”，以及提示词提到手工增长路径却没有对应提交工具，Agent 很容易一直停在资料阶段。

本次改为以下闭环：

1. 用户确认公司、估值日、方法与数据来源，并请求完成估值。
2. LLM 按当前方法补必要基期数据；`propose_facts` 连续暂存，通过来源核验也不自动批准，不再逐批弹卡。
3. `check_preparation` 使用真实组装器在隔离副本上检查可计算性，不依赖模型写出的旧缺口清单。预览不会修改正式事实状态，也不会计算或发布正式估值。
4. 历史充分时走既有历史自动预测；历史不足时，可通过 `propose_forecast` 提出十年三情景预测、WACC、永续增长率、依据及风险。预测是单独的判断，不伪装为历史披露。
5. 模型输入齐备后停止非必要取数，展示整套方案。用户确认一次，系统直接交接财务校验、估值区间、敏感性与报告；不再要求第二次“开始”。
6. 同时选择多种方法时逐项检查可执行性。只要一种已选方法完整，最终确认卡就展示可执行方法以及被排除方法的具体数据原因；确认后按可执行子集计算。单轮同一目的最多三组不同检索，达到上限后不再轮询，而是一次性请求补充正式数据或调整方法。

仅研究资料、解释概念等请求仍保留原有模式，不自动授权计算。旧会话的零散候选确认可转入持续建模，原始来源、警告和用户批准记录保留。

## 保留的专业与安全边界

- 不能用假设、零、搜索摘要或模型记忆填补历史收入、股数、现金、债务等必要事实。
- 显式预测必须完整覆盖十年及三个情景，采用小数比例，检验有限值、情景排序和 WACC > g。
- 单一完整基期加已确认显式预测可进入 DCF；历史不足风险写入假设依据与正式结果。旧的零散比较期仍留在研究记录，不冒充完整历史输入，也不计算虚假的历史 CAGR。
- 方法切换须确认；数据缺失导致的方法降级与财务、预测一起放在最终整套方案卡中确认，不静默删减。公司、日期、行业、方法或来源发生改变后，旧预测失效并留在审计记录。
- 集中确认前重新核验证据；方案变化或证据失效不会沿用旧批准。财务勾稽、合理性校验仍可阻止计算。
- 修改现有财务事实仍要求 `replaces`，旧值只有在最终批准时才被替换。
- 原有 Tushare 模块未修改，纯网页及上传路径不静默改用 Tushare。

## 新增交互

CLI 和网页的默认示例改为完成估值、敏感性及报告。CLI 选择公司后的开场也不再请求“先整理资料”。

集中确认卡展示财务基期、估值日、方法、WACC/g、十年情景路径、预测依据、风险与基期输入。不会预先选中批准；可以先修改。输入“确认估值方案并计算”仅在当前确有完整方案卡时生效，附带修改或否定不会触发批准。

## 验证范围

最终回归：后端 **301 项通过**（1 条既有 Starlette/AnyIO 弃用警告，146.67 秒）；前端 **8 项状态测试、10 项组件检查通过**，静态检查与生产构建通过。提示词版本为 `research-2026-09-25.12`。

使用现有 Conda `economic_agent`，没有新增 Python 环境。新增 `tests/test_valuation_first.py`，覆盖连续分批暂存、回合内可用的提交工具、缺失历史事实保护、无未来信息、范围变更、候选更正、预测参数校验、文字批准和修改方案后的再次复核。

四个不同公司标识的**合成离线案例**均走过：脚本模型编排 → 多批原文提取 → 单次模型复核 → 确定性 DCF → 十年预测与敏感性 → Excel/PDF 报告 → 离线复算校验。它们不是四家真实公司的估值，也不能替代真实模型的能力评测。

网页通过状态单元测试、虚拟 DOM 组件检查、静态检查和生产构建；另在真实浏览器的合成页面验证确认卡展开、窄窗口显示、未选择时禁用提交、主动选择后启用。临时页面及预览服务已清理，不涉及真实研究数据库。

本轮没有调用真实商业 LLM 或 Tavily 做端到端验收，也没有对全部行业或真实公司准确性作保证。真实年报解析、资料可得性、模型调用稳定性和现场联网表现仍需独立实测；扫描件 OCR 等既有边界未改变。

## 使用

重启 CLI 或后端，激活 `economic_agent`，重新连接模型及需要的搜索服务。恢复旧会话后输入“继续”，或直接提出“请对某公司进行估值，给出区间、敏感性分析和报告”。遇到必要事实确实无法取得，系统应给出具体阻塞与最小补充选择，不能以编造结果换取流程完成。
