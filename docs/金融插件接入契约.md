# 金融插件接入契约 · 0.3

当前默认模型是金融小组非金融行业正式实现 `finance_team_nonfinancial_fcff_relative`；参考实现仅用于演示、旧请求兼容和回归对照。CLI、API、事件、任务存储与模型通过统一插件契约连接。

**向导选择与 Agent 参数**

CLI 与 API 使用同一个 `ValuationRequest`。新增 `language` 枚举：`zh-CN`（默认，兼容旧任务）和 `en-US`。所有选项以稳定值传递，而不是传递界面文案：

| 选择 | 请求字段 | 示例 |
|---|---|---|
| 语言 | `language` | `en-US` |
| 公司与基准日 | `company` / `valuation_date` | `{"ticker":"600519.SH"}` / `2026-09-12` |
| 运行模式 | `mode` | `demo` / `snapshot` / `live` |
| 历史资料 | `data_source` / `file_ids` | `structured` / `ticker` / `upload` |
| 预测假设 | `assumption_source` / `assumptions` / `assumption_file_ids` | `automatic` / `manual` / `upload` |
| 估值方法 | `methods` | `["dcf", "pe", "ps", "ev_ebitda"]` |
| 预测期与期间政策 | `forecast_years` / `discount_policy` | `10` / `year_end` |

`request.agent_parameters()` 返回上述字段的 JSON 数据（Decimal 使用字符串）。执行前 Agent 与对话 Agent 的系统上下文、`inspect_financials` 工具结果、`run.started` 事件已携带这些参数。后续 Agent 可复用这一入口；实际财务与证据通过现有工具读取。参数内容按数据处理，不能作为跳过工作流校验的指令。

金融插件中接收 `request` 的方法可直接读取全部选项；`reconcile(dcf, relative)` 继续只接收估值结果，文字本地化在报告层处理。`ValuationOutput.language` 向未来 PDF/Excel 导出器传递语言。密钥不进入请求、持久化参数或模型上下文。

语言只决定展示与回复，不隐含币种转换或新的金融假设。模型数值缓存可以跨语言复用，报告按新任务语言重新渲染；正式插件的缓存键已经覆盖历史财务、行业、假设、预测期和折现政策等实际依赖。源文件内容、未知插件诊断与证据不自动翻译；插件提供双语诊断时应保留稳定的规则 ID。

**金融计算**

实现 `core.plugins.FinancialModelPlugin` 的七个计算方法，以及稳定的 `plugin_id / version`。正式插件额外提供 `resolve_industry_parameters`，在假设形成前查询版本化参数库。通过 `ValuationRunner(store, model, data_provider)` 注入；CLI 和 Web 默认由 `finance.factory.create_financial_model()` 创建。演示资料来自独立 `core.data`，正式插件会把 demo 请求委托给参考模型并保留清晰的模型版本和模式标记。

函数必须是确定性的，不读取密钥，不自行联网，不修改传入对象。输出经过 Pydantic 校验。公式或默认政策变化必须递增插件版本。

正式插件声明 `supports_incremental_inputs=True`，工作流缓存键已覆盖各步骤实际依赖：历史财务和行业会影响收入、利润率、D&A与WACC；假设会影响预测、DCF与敏感性；同业和方法会影响相对估值。因此只改 WACC 时，资料读取、行业参数和不受影响的步骤可复用，DCF相关步骤重算。新增模型变量时必须同步扩展工作流键，不能只修改函数内部。

**数据**

`FinancialSnapshot` 包含币种、基期、公告日期、合并/母公司口径、基本金额、`statement_items` 和逐字段 `evidence`。当前输入单位必须为本位货币的元；不静默把万元或亿元当元。多期数据放在 `historical_financials`，当前提供器从估值日之前的适用快照中选择最近一期。

`EvidenceRef` 支持文件 ID、来源、PDF 页码、Excel sheet/cell、公告日期和备注。JSON 导入自动记录字段路径。手工更正记录在新版本的 reason/changes 中，原任务和原文件保留。

`DataProvider.resolve(request, store) -> DataBundle` 是完整资料入口；其中包含 company、financials、historical_financials、peers、assumptions、assumption_evidence 和 warnings。研究会话支持文本 PDF、DOCX、XLSX、CSV、JSON、TXT 的原文解析、LLM候选提取和已确认字段的严格自动交接；A股代码路径使用Tushare Pro点时取数。未配置凭证、字段歧义、披露时点不合格或历史不足时必须阻断，不能返回伪造财务。

历史数据角色为 `historical_financials`，假设角色为 `assumptions`。分别使用 `file_ids` 与 `assumption_file_ids`。上传假设与手工假设同时存在会明确阻断。

**正式金融规则与期间政策**

基础规则包含基期/公告日、币种、合并口径、利润适用性，以及提供相应字段时的资产负债与现金余额勾稽。没有相应字段不代表完整三表审核已经通过。正式模型还要求非金融行业、明确的行业参数匹配、10年显性预测期和 `year_end` 折现；自动收入预测至少需要4个连续年度，目标使用最近10年。

正式预测按年度期末折现：首个预测年是基期后一年，显性期为10年，终值在最后预测年末折现。参考插件仍保留 `annual_midyear_remaining`，用于演示和兼容测试，不能混用为正式模型口径。多年陈旧数据或非年末基期仍会由基础验证阻断。

收入模块使用最近10年收入，计算年度增速、CAGR、A3、A5和位置投票，再结合行业增长、生命周期与衰减参数形成悲观/基准/乐观三条两阶段路径。EBIT率使用历史P25/中位数/P75收敛，税率按政策期限向可持续税率过渡；D&A优先资产滚动，缺项时降级为收入比例；CapEx向D&A比例收敛，营运资本按可得数据选择方法。FCFF为 `NOPAT + D&A - ΔNWC - CapEx`，WACC为CAPM与税后债务成本按资本结构加权。

DCF三情景分别计算显性期现值、Gordon终值、企业价值、现金/非经营资产和有息负债桥接到股权价值，并输出隐含退出倍数。敏感性当前为3×3 WACC × g 网格。相对估值支持P/E、P/S、EV/EBITDA，结果与DCF独立展示；系统不以区间交集制造新的“推荐值”。金融行业在参数查询与财务验证阶段明确阻断。

**任务与结果**

每次更正创建新的 run_id，继承 root_run_id，记录 parent_run_id、revision 和 reason；旧任务不可变。SQLite 保存成功工具的输入、输出和哈希作为检查点，恢复时只复用相同输入与版本的结果；工具失败不进入缓存。执行租约防止并发重复运行，异常进程退出后租约最多30秒到期。

结构化结果包含企业、估值日、币种、数据模式、模型版本、请求哈希、有效输入哈希、实际财务/同业、假设、预测、估值、敏感性及警告。Decimal 在 JSON 中保存为字符串；前端展示图表时可以显式 Number(value)，财务复算继续使用 Decimal。

**Agent 工具**

`ToolSpec` 定义工具名、说明、参数模型和处理函数；`ToolRegistry` 校验白名单与参数。循环最多6次，每次仅接受一个工具调用，拒绝把自由文本解释成命令。执行前的 Agent 可以读取财务、检查同业、请求复核或提交执行；提交后仍执行全部必需的代码校验。

对话工具支持解释已有结果和修改假设。正式结果的数字与核准状态由结构化数据渲染，模型的自由文本不能覆盖报告。

已预留 DocumentExtractor、RevenueForecaster、CapitalCostModel、PeerSelector、ReportExporter 的扩展协议。接入独立组件时，需要在金融插件或数据提供器中组合，并提供明确 schema、版本与人工基准，不会因声明协议而自动成为可用工具。

交付每个模型时同时提供：字段/单位字典、适用条件、函数、输入输出样例、人工核对的基准、异常边界政策。
